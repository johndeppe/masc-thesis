\section{Tracking with Software-loaded TLB}

Inspired by ABIS's observation that an operating system can track which processor cores have a particular \ac{PTE} cached in its \ac{TLB}s and then use that tracking to reduce TLB shootdown overheads\cite{amit_optimizing_2017}, we add an madvise() to Linux that allows a user program to designate a region of virtual memory for such tracking.

Recall from Section TODO REFERENCE that ABIS performs shenanigans with address spaces to foil the hardware page walker and instead fault when accessing regions of interest. We seek to ameliorate this substantial overhead. Recognizing that only some memory regions in a program will likely have sparse access, we only track regions designated by the programmer. Future systems could automate this in with profiling similar to Linux's NUMA migration. Our software-loaded TLB entries could be used in the NUMA case where Linux wants to extend their profiling, even. (advocacy for software-loadable TLBs?)

We accomplish the tracking by invalidating \ac{PTE}s, so that the hardware page walker will now produce a page fault instead of simply filling the \ac{TLB}.

we'll allocate PTEs with extra space for a cpumask that tracks cores have that PTE in their TLB. (TODO: Where do these PTEs go? When do they get allocated?)

We detect TLB presence by avoiding the hardware page table walker. The process of interest gets an empty satp entry, so all page walks will fault. When we fault, we use c920's TLB-manipulation registers to insert the appropriate TLB entry and then mark the appropriate cpumask. We can then also clear the cpumask of the evicted entry, which also appears in the TLB-manipulation registers.
